# LM393 레이저 커튼 — 재귀반사 차단 설명서

## 한 줄 요약

값싼 LM393 포토 모듈은 **손가락/BB의 산란광을 잡지 못한다.**  
화면 테두리 **재귀반사 테이프의 강한 귀환**을 평소에 읽고, 물체가 레이저를 가려 **신호가 짧게 끊기는 순간**을 터치로 본다.

펌웨어 기본 모드: `mode int` (Beam Interrupt).  
상세 코드: `laserModuleL|R/SensorDetect.h`

관련: [BDS Check](../docs/bds-check.md) (HID 좌표 검증)

---

## 1. 왜 산란 검출이 안 되는가

센서가 고장난 것이 아니다. **소자 감도 한계**다.

| 원인 | 내용 |
|------|------|
| 수신 광량 | 고속 스캔 빔이 손가락에 맞으면 빛이 사방으로 퍼진다. 수십 cm~수 m 떨어진 수광부에 도달하는 에너지는 **µW 이하**로 급감한다. |
| 모듈 설계 | 렌즈·고감도 증폭이 없다. **수 cm 이내 직접 반사** 또는 **빔 차단**용 저감도 비교기 보드다. |
| DO 문턱 | 가변저항을 아무리 돌려도, 산란광이 만든 미세 전압은 LM393의 HIGH/LOW 기준을 넘지 못한다. |

예전에 코드가 가정한 방식은 이것이었다.

```
스캔 빔 → 물체에 맞음 → 산란광이 PD로 돌아옴 → DO가 뒤집힘 → HIT
```

이 경로는 **현재 부품으로는 물리적으로 불가능**하다.  
AO(아날로그)조차 손가락 통과 때 거의 안 움직이면, 산란 직접 검출은 포기하고 **반드시 차단 방식**으로 간다.

## 2. 차단(Beam Interrupt)이 하는 일

재귀반사 테이프는 들어온 빛을 **거의 온 방향으로 되돌려** 보낸다. LM393이 읽을 수 있을 만큼 강하다.

```
평소:  레이저 → (화면 평면 스캔) → 테두리 테이프 → 강한 귀환 → 센서 beam=1
터치:  레이저 → 손가락/BB가 가림 → 테이프에 도달 못함 → 짧은 소실 → HIT
```

코드는 **빛이 나타난 순간이 아니라, 귀환이 짧게 사라진 순간**을 HIT로 본다. (역방향 로직)

```
        retro tape (상단 + 반대편 세로)
   ┌─────────────────────────────────┐
   │  스캔 광선이 항상 테이프에 맞음  │
   │         ● 손가락/BB             │
   │          ╳ 귀환 차단 = HIT      │
   └────[ L 레이저+PD ]── [ R ]──────┘
         좌하단 θ1           우하단 θ2
```

좌하단(L)은 오른쪽·위쪽으로 90°를 쓸고 **θ1**을 잰다.  
우하단(R)은 왼쪽·위쪽으로 90°를 쓸고 **θ2**를 잰다.  
R이 두 각으로 삼각측량해 USB HID 클릭을 보낸다.

\[
\tan\theta_1 = Y/X,\quad \tan\theta_2 = Y/(W-X)
\]
\[
X = W\cdot\tan\theta_2/(\tan\theta_1+\tan\theta_2),\quad Y = X\cdot\tan\theta_1
\]

원점: 화면 **좌하단**. X→오른쪽, Y→위.

## 3. 테이프 시공 (이 방식이 먹으려면)

코너에서 나가는 모든 광선이 **열린 화면을 가로질러 테두리에 닿는다.**

- 작은 각(수평에 가까움) → **반대편 세로 테두리**
- 큰 각(수직에 가까움) → **상단 테두리**
- 경계는 맞은편 코너로 가는 대각선

따라서 테이프는 **상단 + 그 노드의 먼 쪽 세로변**에 **끊김 없이** 붙인다.

| 노드 | 설치 | 테이프 |
|------|------|--------|
| L (좌하단) | 화면 왼쪽 아래 | **상단 전체 + 오른쪽 세로** |
| R (우하단) | 화면 오른쪽 아래 | **상단 전체 + 왼쪽 세로** |

실무에서는 프레임 안쪽 네 변에 한 바퀴 두르는 것이 가장 안전하다. L·R이 같은 테이프를 공유해도 된다.

### 반드시

- 재귀반사(retroreflective) 테이프. 일반 흰색 종이·무광 페인트는 귀환이 약하다.
- 화면 **앞면 평면**(레이저가 지나가는 커튼 면)과 같은 높이에 붙인다. 스크린 유리 뒤·프레임 바깥으로 빠지면 빔이 테이프를 안 맞는다.
- 모서리에서 이어지게. 중간에 수 cm 빈 곳이 있으면 그 각도마다 가짜 “끊김”이 난다.
- 주름·들뜸을 피한다. 재귀반사는 입사각이 커져도 제자리로 돌려보내지만, 접히면 방향이 틀린다.

### 센서·레이저 광축

PD는 레이저 출사점 **바로 옆**에 두고, 화면 평면을 바라보게 한다.  
스캔 빔과 PD 시야가 같은 평면을 보도록 높이를 맞춘다.  
PD가 바닥·천장만 보면 테이프 귀환을 놓친다.

## 4. 배선

### 4.1 LM393 모듈 → Teensy 4.1

보드를 **센서·가변저항이 위, 4핀 헤더가 아래**로 놓고 왼쪽→오른쪽:

```
     [ 포토다이오드 ]
     (파란 가변저항 / LM393)
  ┌──┬──┬───┬───┐
  │AO│DO│GND│VCC│
  └──┴──┴───┴───┘
```

| 모듈 실크 | Teensy | 비고 |
|-----------|--------|------|
| AO | **A1 (Pin 15)** | 아날로그. **A0(Pin 14) 금지** — TFT 백라이트 |
| DO | **Pin 5** | 디지털. CHANGE 인터럽트 |
| GND | GND | 공통 |
| VCC | **3.3V** | **5V 금지.** DO가 5V면 Teensy 4.1 핀 손상 |

점퍼 색은 보드마다 다르다. **실크를 따른다.**

### 4.2 레이저 (Pin 9, NPN 로우사이드)

레이저 GND를 Teensy GPIO에 직접 물리지 않는다 (과전류).

```
레이저 RED  (+) ──► Teensy 3.3V  또는 LM2596 5V (더 밝음)
레이저 BLACK(-) ──► NPN Collector (2N2222 등)
NPN Emitter     ──► GND
Teensy Pin 9    ──► ~1kΩ ──► NPN Base
```

`laser on` → Pin9 HIGH → 트랜지스터 ON.

멀리서 테이프 귀환이 약하면 레이저 +를 **LM2596 5V**로 옮겨 본다. (센서 VCC는 그대로 3.3V)

### 4.3 전원

| 경로 | 연결 |
|------|------|
| LM2596 5.0V OUT+ | Teensy VIN |
| LM2596 OUT− | Teensy GND = 센서 GND = 레이저 GND 경로 = 모터 GND |
| 모터 24V V | 모터 보드만. **Teensy에 넣지 말 것** |

USB 포트가 위일 때 Teensy 우측 상단: VIN / GND / 3.3V.

### 4.4 L ↔ R UART (Serial1, 1 Mbps)

```
L TX1 (Pin 1) ──► R RX1 (Pin 0)
L RX1 (Pin 0) ◄── R TX1 (Pin 1)
L GND ────────── R GND     ← 빼먹으면 링크 불안정
```

R USB Type: **Serial + Keyboard + Mouse + Joystick** (HID `Mouse.moveTo`/`click`).

## 5. 가변저항 (DO 임계)

파란 트리머는 **비교기 문턱**이다. 산란광을 “더 잘 듣게” 해주지 않는다.  
목적은 **테이프 귀환이 있을 때 DO가 확실히 수광 쪽**이 되게 하는 것이다.

기본 가정: `SENSOR_DO_ACTIVE_LOW=true` → **DO=LOW 가 수광(beam present).** 흔한 LM393. DO-LED가 같이 켜지는 보드가 많다.

1. 레이저 ON, 모터는 아직 정지. 빔이 테이프(또는 가까운 재귀면)를 비추게 한다.
2. 트리머를 천천히 돌려 **귀환 있을 때 DO-LED ON(또는 `sensor`에서 `beam=1`)** 이 되게 한다.
3. 손을 센서 바로 앞이나 빔 경로에 넣어 귀환을 가리면 `beam=0`으로 뒤집혀야 한다.
4. 경계에서 LED가 깜빡이면 주변광(형광등·햇빛)을 줄이거나, 트리머를 수광 쪽으로 조금 더 민다.
5. 극성이 반대면(`beam`이 귀환과 반대로 움직임) `SensorDetect.h`의 `SENSOR_DO_ACTIVE_LOW`를 `false`로 바꾸고 다시 플래시한다.

스캔 중에는 빔이 테이프를 스칠 때만 수광이 펄스처럼 보인다. **정지 상태에서 먼저** 맞추고, 그다음 `start`한다.

## 6. 펌웨어 검출 모드

부팅 기본값: **`int`** (차단). 재부팅하면 기본으로 돌아간다.

| `mode` | 이름 | HIT 조건 | 언제 쓰나 |
|--------|------|----------|-----------|
| `int` | Interrupt | DO에서 **짧은 수광 소실** (2~1500µs) | **정식. 테이프 시공 후** |
| `ao` | Analog | AO가 `aoth` 임계를 넘김 | `ao` 명령 span이 클 때만 |
| `diff` | Diffuse | 짧은 **수광 펄스** (옛 산란) | 디버그. 원거리에서는 실패 |

### 6.1 `int` — 펄스 폭 필터

스캔이 테이프 구간을 벗어나면 긴 암흑이 생긴다. 그걸 터치로 오인하면 안 된다.

| 상수 | 값 | 의미 |
|------|----|------|
| `SENSOR_BREAK_MIN_US` | 2µs | 이보다 짧은 글리치 무시 |
| `SENSOR_BREAK_MAX_US` | 1500µs | 이보다 긴 암흑 = 스캔 밖. 무시 |

물체가 빔을 가리는 시간은 보통 수~수백 µs다.  
각도는 **소실이 시작된 시각**(펄스의 앞모서리)과 Sync(0°)의 차로 계산한다.

DO는 `loop()` 1ms 폴링이 아니라 **Pin5 CHANGE ISR**로 잡는다. 모터 기동 중에는 `delay(1)`도 끈다.

### 6.2 `ao` — 소프트웨어 임계

스캔 펄스는 너무 짧아 `analogRead`가 놓치기 쉽다.  
손 차단처럼 **느린 변화**나, AO span이 큰 근접 실험용이다.

- `aodir high` (기본): AO **>** `aoth` 이면 HIT. 전형적으로 어두울수록 AO가 올라간다.
- `aodir low`: AO **<** `aoth` 이면 HIT.

## 7. USB 시리얼 명령

양쪽 115200. 한 줄씩 보내고 Enter. TFT는 ASCII 20자/줄 제한이 있어 긴 안내는 Serial에만 나온다.

### 7.1 L·R 공통 (센서)

| 명령 | 동작 |
|------|------|
| `sensor` | `mode`, `beam`, `hit`, `DO`, `AO`, `aoth`, `aodir` |
| `ao` | 3초 AO 스트림 + min/max/span |
| `ao 5000` | 지정 ms (200~20000) |
| `mode` | 현재 모드만 출력 |
| `mode int` / `diff` / `ao` | 검출 모드 변경 |
| `aoth` / `aoth 400` | AO 임계 조회/설정 (0~1023) |
| `aodir` / `aodir high` \| `low` | AO HIT 방향 |
| `status` | 모터·sync·센서 요약 |
| `laser on` \| `off` | Pin9 |
| `help` | 짧은 명령 목록 (TFT용) |

`ao` 스트림은 **Serial에 숫자만** 20ms마다 찍는다. TFT를 막지 않기 위함이다. 끝나면 요약이 TFT에도 나온다.

### 7.2 모터·링크

| 명령 | L | R |
|------|---|---|
| `start [hz]` | 로컬 모터 | 로컬 + UART `M,1` → L |
| `stop` | 로컬 | 로컬 + `M,0` |
| `clk <hz>` | 100~10000 | 동일 |
| `ping` | (echo만) | UART 왕복 확인 |
| `theta <deg>` | θ1 강제 송신 | — |
| `theta2 <deg>` | — | 수신 θ1과 삼각측량 |
| `inject t1 t2` | — | θ1·θ2 주입 후 HID |
| `hid on` \| `off` | — | 마우스 출력 |

R이 `start`하면 L이 나중에 켜져도 2초마다 `M,1`을 다시 보낸다.

## 8. 첫 기동 체크리스트

펌웨어를 L·R 모두 다시 올린 뒤.

### 8.1 전원·극성 (모터 OFF)

1. `sensor`  
   - PWR-LED ON. `AO`가 0 고정/1023 고정이면 배선·VCC부터.
2. `laser on`
3. 빔을 테이프(또는 재귀면을 센서 가까이)에 비추고 `sensor`  
   - 목표: `beam=1` (수광). 안 되면 §5 트리머.
4. 손으로 빔/수광부를 가림  
   - 목표: `beam=0`. 안 뒤집히면 거리·광축·트리머.

### 8.2 AO 진단 (산란이 되는지 확인)

레이저 ON. 가능하면 모터도 `start`.

```
ao 3000
```

3초 안에 손가락을 스캔 평면으로 지나게 한다.

| 로그 | 의미 | 다음 |
|------|------|------|
| `[ao] dead` (`span` &lt; 8) | AO도 안 움직임. 산란 검출 불가 | **테이프 + `mode int`** |
| `[ao] ok` | 임계값으로 쓸 만큼 변함 | `aoth <중간값>` → `mode ao` 시험 가능 |

`dead`가 나와도 정상이다. 그 결과가 이 설명서의 전제다.

### 8.3 차단 검출 (정식)

1. 테이프 시공 확인 (§3)
2. `mode int` (부팅 기본)
3. `laser on` → `start` (R에서 하면 L도 따라옴)
4. `[motor] LOCKED` 가 나오는지 확인 (LD)
5. 스캔 평면에 손가락  
   - 성공: `[hit] w=…us` 그리고 L은 `[link] TX T1 …`, R은 `[tri]` / `[hid]`
6. Unity `BdsCheck` 씬, Game 뷰 **1920×1080** — [bds-check.md](../docs/bds-check.md)

HID만 먼저 보려면 R에서 `inject 30 30`.

## 9. 로그 읽는 법

| 로그 | 의미 |
|------|------|
| `mode=int tape` (setup) | 차단 모드로 기동 |
| `beam=1` | 지금 수광(테이프 귀환 또는 직접광) |
| `hit=1` | 현재 레벨이 “차단/암흑” 쪽. **정지·빔이 테이프를 안 볼 때도 1일 수 있다.** 실제 터치는 `[hit] w=` |
| `[hit] w=80us` | 필터를 통과한 짧은 소실. 이 앞모서리로 θ 계산 |
| `[hit] no sync` | Sync(Pin6) 없음. `theta` / `theta2`로 수동 시험 |
| `[ao] 12..14 span=2` / `dead` | 아날로그 무반응 → int+테이프 |
| `[ao] ok` / `try aoth 400` | 제안 임계 |
| `[tri] no th1/stale` | R이 θ2는 있는데 L의 T1이 50ms 안에 안 옴 |
| `[link] FAIL` | UART·GND·L 전원. R에서 `ping` |

`hit=` 과 `[hit]` 를 혼동하지 말 것.  
**터치 이벤트는 `[hit] w=` 한 줄이다.**

## 10. 문제 해결

| 증상 | 의심 | 조치 |
|------|------|------|
| 손가락을 넣어도 `[hit] w=` 없음 | 테이프 없음/빔이 테이프를 안 맞음 | 시공·광축. 정지 상태에서 `beam`이 귀환에 따라 뒤집히는지 |
| 스캔마다 가짜 HIT | 테이프 공백, MAX 펄스와 비슷한 긴 소실 | 테이프를 이어 붙임. 트리머가 너무 예민하면 주변광 |
| `w=` 는 나오는데 좌표가 틀림 | Sync 0° / `SCAN_ANGLE_DEG` / L·R 자리 | Sync 배선. 화면 W mm (`SCREEN_WIDTH_MM`) |
| AO가 항상 같음 | 정상일 수 있음 | `dead` → int. 배선 의심은 VCC/GND/A1 확인 |
| `hit=1` 이 계속 | 레이저 OFF, 빔이 테이프 밖 | 레벨일 뿐. `laser on` + 테이프 |
| Teensy가 리셋/죽음 | 센서 5V | VCC를 3.3V로. 5V DO는 비내성 |
| R 컴파일 실패 `Mouse` | USB Type | Serial + Keyboard + Mouse + Joystick |
| Unity에 클릭 없음 | HID 해상도, `hid off` | Game 뷰 1920×1080. `hid on`. `inject 30 30` |
| L만 HIT, R 삼각측량 실패 | UART T1 | `ping`, GND 공통, L `start` |

`mode diff`로 “예전처럼” 돌려도 **원거리 산란은 살아나지 않는다.**

## 11. 핀맵 요약 (L·R 동일)
